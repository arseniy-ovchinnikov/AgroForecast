## 1. Почему пайплайн не был выполнен до конца в облаке

Сессия выполнялась в облачном контейнере. Мост к диску пользователя
передаёт файлы, но **не выполняет код на локальной машине**, а на передачу
файла действует ограничение **400 МБ**. Файл ERA5 `data_stream_moda.nc`
весит **732 МБ** — загрузить его в облако невозможно, а обработать на месте
нечем. Вся статистика Росстата (файлы до 8 МБ) была загружена и обработана
полностью.

Поэтому в облаке выполнено всё, кроме шага 1 (агрегирование ERA5), а весь
код написан и **проверен на сквозном прогоне** с синтетическим NetCDF,
воспроизводящим структуру реального файла (те же переменные, те же единицы,
та же временная ось 160 шагов 04.2000–07.2026).

## 3. Что нужно сделать в локальной сессии

```bash
cd C:\AgroForecast

# 0. Убрать прежнюю реализацию (data/ не затрагивается)
python scripts/00_cleanup.py           # показать план, диск не меняется
python scripts/00_cleanup.py --apply   # удалить
#   варианты: --archive              перенести в archive_old_pipeline/, а не удалять
#             --consolidate-sources  скопировать оставшиеся книги Росстата
#                                    из Desktop\агро в data\Rosstat\_source\
#             --include-external     удалить дубликаты проекта на рабочем столе
#                                    (Desktop\AgroForecast и Desktop\агро\пайтон,
#                                     это ещё ~1,3 ГБ старых копий ERA5)

# 1. Зависимости
python -m pip install -r requirements.txt

# 2. Полный прогон: ERA5 → Росстат → датасет+QC → валидация → отчёт
python scripts/run_all.py

# 3. Проверочный прогноз
python scripts/05_predict.py --year 2024
```

Файл ERA5 должен лежать в `C:\AgroForecast\data\ERA5\data_stream_moda.nc`
(он там уже есть), `ru.json` — в `data\boundaries\`, книги Росстата —
в `data\Rosstat\`.

Шаг 1 читает `data/ERA5/data_stream_moda.nc` (732 МБ). Ориентировочно
2–6 минут и ~4 ГБ ОЗУ: построение индекса «ячейка → регион» для сетки
411 × 1611 занимает около 20 секунд, дальше — 160 месяцев × 5 переменных.

Ожидаемое время: шаг 1 — минуты, шаг 2 — секунды, шаг 3 — секунды,
шаг 4 — примерно 7–15 минут (36 обучений), шаг 6 — секунды.

### На что посмотреть в первую очередь

1. `results/raw_processed/era5_structure.json` — **фактическая** структура
   NetCDF. Поле `spec_issues` должно быть пустым; если нет — расхождение
   с ожиданиями из `configs/config.yaml` (не ошибка, но требует внимания).
2. `results/raw_processed/era5_cells_per_region.csv` — сколько ячеек ERA5
   пришлось на каждый субъект. Регионы с нулём попадут в лог как WARNING.
3. `results/features/qc_report.csv` — ошибок быть не должно.
4. `results/models/model_comparison.csv` — сравнение 14 строк
   (12 комбинаций + 2 эталона).
5. `results/models/khakassia_by_year.csv` — факт/прогноз/ошибка по Хакасии.

### Если что-то упало

* Не найден NetCDF → проверьте `paths.era5_files` в `configs/config.yaml`;
  там перечислены два варианта имени (`data_stream_moda.nc` и
  `data_stream-moda.nc`), используется первый существующий.
* Не хватает памяти на шаге 1 → уменьшите число переменных в
  `era5.variables` и выполните шаг 1 несколько раз, либо сократите
  `features.season_months`.
* `MemoryError` в CatBoost → уменьшите `models.catboost.iterations`.
* Расхождение структуры ERA5 (другие имена переменных/координат) →
  `src/data/era5.py` понимает `valid_time`/`time`, `latitude`/`lat`,
  `longitude`/`lon`; иные имена нужно добавить в `_TIME_NAMES` и т. п.

## 4. Решения, принятые в ходе аудита (чтобы не пересматривать заново)

1. **Целевая переменная — табл. 13.11** «Регионов России» (2000–2024,
   85 субъектов), а не выгрузка ЕМИСС (2010–2024, 78 субъектов).
   Обоснование и таблица сравнения — `docs/DATA_INVENTORY.md`, § 2.
2. **Файлы ЕМИСС по удобрениям, приобретению, убранной площади и
   окончательным итогам посевов содержат только строку «Российская
   Федерация»** — регионального разреза в них нет, в модель они не входят.
   Региональные удобрения берутся из табл. 13.21.1 / 13.21.2.
3. **Валовой сбор и оперативные показатели исключены как утечка**, хотя
   технически доступны.
4. **Автономные округа** ведутся отдельно; Тюменской и Архангельской
   областям сопоставлены строки «без автономного округа» — соответствие
   геометрии проверено программно.
5. **Крым и Севастополь исключены** — нет полигонов в `ru.json`.
6. **160 шагов ERA5 = апрель–сентябрь 2000–2025 + апрель–июль 2026**,
   поэтому 2026 год заведомо неполон и прогноз на него скрипт откажется
   строить (код проверяет это фактически, а не по предположению).

## 5. Что можно улучшить дальше (в порядке ожидаемой отдачи)

1. **Взвешивание климата по площади пашни.** Сейчас климат региона —
   простое среднее по всем ячейкам полигона. Для крупных северных субъектов
   это заметно смещает признаки. Решение: маска пашни (например, ESA CCI
   Land Cover или Copernicus Global Land Cover) как веса в
   `src/data/era5.py::extract_region_monthly`.
2. **Разделение озимых и яровых.** Табл. 13.11 даёт суммарную урожайность;
   у озимых и яровых разные критические периоды. В `Val1_2025_v2.xlsx`
   есть разбивка по РФ, региональной за длинный ряд — нет.
3. **Декадные, а не месячные признаки ERA5** — критические фазы (кущение,
   налив зерна) короче месяца. Требуется другая выгрузка CDS.
4. **Подбор гиперпараметров** внутри временной валидации (вложенная схема),
   сейчас параметры фиксированы в конфиге.
5. **Дообучение на 2025 г.** — панель уже расширена, но климат 2025 г.
   попадает в датасет только при полном сезоне апрель–сентябрь в ERA5.
